# Delegation

Use one role per bounded responsibility. Explorer is read-first. Implementer changes only assigned paths. Reviewer is fresh, independent, read-only. Verifier runs applicable project/profile commands and acceptance checks. Reviewer evaluates implementation; Verifier executes requirements/gates. Do not collapse roles when independent evidence matters.

Dispatch minimum context: goal, rules/paths, owned paths or diff boundary, dependencies, outcome, gate, authority, and current Developer Closure when present. Developer receives one task and may not alter requirements, architecture decisions, canonical state, or tests to conceal failure. It may modify assigned source, format touched files, and execute project-required development gates. Reviewer never fixes or contacts Developer directly; it returns one complete finding batch. QA uses the boundary to distinguish a task failure from `EXTERNAL_DIRTY_WORKTREE`; it executes only approved non-mutating verification and never formats, reverts, or claims unrelated work. Return compact evidence, not reasoning or transcripts.
